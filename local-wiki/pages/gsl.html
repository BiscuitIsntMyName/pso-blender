pso-blender local wiki / gsl

.gsl documented, implemented

Flat, uncompressed archive container (e.g. Data.gsl) bundling many files together - sector-addressed, a holdover from the game's CD-ROM era. Fully implemented in pso_blender/gsl.py.

Confirmed

  • Table of fixed 40-byte entries, no explicit count: [32-byte ASCII filename][U32 sector offset][U32 length][8 bytes padding]. Table ends once it would overlap the smallest offset seen so far.
  • Offsets are in 2048-byte sectors (byte_offset = sector_offset * 2048).
  • Cross-checked against theanine3D/pso_ultimate_importer's gsl_read_archive - identical format.
  • Real Data.gsl (Ephinea): 1524 entries, ~71.7MB. Contains 13 distinct extensions: BIN, BML, CPT, DAT, EVT, PR2, PR3, PRS, REL, RLC, SCC, XVM.

In-game loading behavior

  • Per the user, not independently verified: Data.gsl is read once at game startup, not per-map-load like .rel/.xvm - a change to it needs a full game restart to show up. Some modders reportedly get away with dropping a modified file loose outside the archive and having the game pick it up anyway (a loose-file-override mechanism, if real) - worth checking, since it would make iterating on any future Data.gsl-related work far faster than editing/repacking the whole archive each time.
Code: pso_blender/gsl.py. UI: the N-panel GSL browser (gsl_browser_menu.py) - search/filter/extract any entry with no repacking needed.
