PRS compression documented, implemented (decode + encode)

Not a file extension - a general-purpose LZ-style compression algorithm SEGA used across several PSO file types. Encountered here as an optional payload compression inside .bml (CompressionType.PRS, the ASCII byte 'P').

Confirmed

  • Bit-flag-driven LZ77 variant: a running control-byte supplies one flag bit per decision, consumed LSB-first, refilled from the stream a byte at a time once exhausted (Decoder._read_bit, prs.py).
  • Per bit read: a set flag bit means "literal byte, copy it straight through". A clear flag bit means "back-reference" - a further bit distinguishes a short encoding (2-bit size, 0-2 -> size 2-4, encoded inline with the offset) from a long encoding (separate size byte, offset 0 terminates the stream entirely - the end-of-stream marker).
  • Both directions implemented: Decoder/decompress() and Encoder/compress() - this addon can both read and write PRS-compressed .bml payloads.

Cross-reference: pso_ultimate_importer

  • Their decompress_prs (_archives/pso_ultimate_importer-main/__init__.py:2960, explicitly labeled "SEGA PRS/LZS") implements the exact same algorithm shape as this addon's own prs.py: same bit-flag decision structure, the same short-encoding (2-bit inline size, 0 -> read an extra size byte) versus long-encoding (2 more flag bits for size, separate offset byte) split, and the same two window sizes (0x2000 for the short/2-byte-offset form, 0x100 for the long form). Solid independent confirmation this addon's PRS implementation matches the real algorithm, not just an approximation of it.
